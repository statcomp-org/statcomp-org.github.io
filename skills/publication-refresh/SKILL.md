# Publication refresh

Maintain the publication records and package references in this repository
using current public evidence. The public Google Scholar profile is the
discovery source; no user export is needed:

<https://scholar.google.com/citations?user=4jVhnnEAAAAJ&hl=en>

## Publication records

1. Read the public profile and identify works that are not yet represented in
   `jyan.bib` or `jyan-cv-extra.bib`. Search by DOI, title, and author list to
   detect existing records and duplicates. If Google Scholar rate-limits direct
   access, retry and use indexed public profile results. Continue only with
   records whose identity can be verified; report any remaining access gap.
2. Treat Scholar records as leads, not authoritative metadata. Resolve each DOI
   through the DOI landing page and check the publisher's record for title,
   authors, publication year, journal, volume, issue, pages or article number.
   For records without a DOI, use the journal or publisher page. Preserve
   accurate existing BibTeX keys and DOI fields; do not create a duplicate key
   for a work already listed.
3. Keep accepted papers without final publication details in `jyan.bib` using
   the established `year={YYYY+}` and `note={Forthcoming}` markers. Remove both
   only when final volume and page or article-number information is available.
   Do not infer final status from an online-first date alone.
4. Follow the existing CV ordering rules. Within a publication year, order
   records by author names as the user specified. Preserve category and
   forthcoming placement generated by the project. Do not hand-edit generated
   files.

## Package-reference audit

Review every R package entry in `software.qmd` during each package audit; do
not stop after checking the packages touched by a new paper.

1. For each package, inspect its official CRAN citation page or `DESCRIPTION`.
   For archived packages, use archived CRAN metadata/source. Check the
   reference manual, README, or maintainer repository when the citation or
   description points to specific method papers or package documentation.
2. Compare the package's explicitly recommended citations and documented
   methods with `jyan.bib` and `jyan-cv-extra.bib`. Include a publication only
   when the package source supports that association. A similar topic, shared
   coauthor, or another package by a coauthor is not sufficient evidence. Do
   not attribute a coauthor's separate package or its paper to this package.
3. Keep each package's reference list in year order and, within a year, author
   order. Match existing author formatting, DOI links, and reference style.
   Link the package name in each detailed section's heading directly to CRAN
   or its maintainer repository; use an archive link for archived packages.
4. If the package source does not establish a publication reference, leave the
   reference list empty. Do not fill gaps by guessing. Record the source used
   when a reference is added or changed so the decision is reviewable.

## Repository workflow

Keep edits focused on source files. In particular, do not edit generated
`publications.qmd` or `cv-publications.tex` directly. After updating sources,
run:

```sh
make publications
make cv-publications
make check-cv-publications
git diff --check
```

Inspect the complete diff for ordering errors, status-marker changes, duplicate
records, unrelated edits, and incorrect package attributions. Summarize what
changed and any metadata or source-access uncertainties. Do not commit, upload,
or publish unless explicitly requested.

The user maintains the public Scholar profile; no citation export or additional
curation step is expected from them. A refresh still begins when this repository
update is requested. Do not claim that a background schedule is running.
